# Security guidance and vulnerability reporting

## Reporting a vulnerability

**No dedicated private disclosure contact or enabled GitHub private vulnerability-reporting channel is verified for this repository.** Selecting and publishing a secure channel is a maintainer decision. Do not post sensitive unpatched vulnerabilities, exploit details, secrets, or private infrastructure information in ordinary public issues. Obtain a verified private channel from the maintainer before transmitting sensitive evidence; if none is available, do not publish that evidence.

A private report should identify the affected commit/component, impact, and minimal reproducible steps using disposable data, with credentials/key material removed. Restrict testing to local fixtures or explicitly authorized systems. There is no approved response-time SLA, bounty, supported-version promise, or coordinated-disclosure deadline documented here.

## Application-specific boundaries

- **Local private material:** CSR/private/public keys are created with browser Web Crypto; passwords, tokens, recovery codes and related secrets use secure browser randomness. These tools do not send entered/generated material to application APIs or persist it in browser storage. Exportable keys remain accessible in browser memory/output. This does not protect against malicious extensions, malware, screenshots, compromised devices, or guarantee memory erasure.
- **Clipboard:** copying is explicit user action. OS clipboard/history/monitors are outside application control. Use disposable data for testing and clear copied secrets when practical. Clipboard failure must not be mistaken for a successful copy.
- **Backend authentication:** protected routes require the server-side shared `X-Toolbox-Backend-Secret`; exact `/healthz` is exempt. This protects service access, not user identity/login. Missing configuration fails closed. Never ship the credential in browser assets, `VITE_*`, URLs, logs, or issue evidence.
- **Pages boundary:** browsers call relative `/api/...`; the Function supplies authentication and strips/reconstructs forwarded identity, with manual upstream redirects. The operator must supply bindings and safe transport. HTTP upstreams are still accepted by Pages, so verified HTTPS is an operational requirement for untrusted networks, not an enforced handler guarantee. See [proxy details](frontend/functions/README.md).
- **Forwarded identity:** backend rate identity defaults to socket peer. Enable `TRUST_TOOLBOX_PROXY_HEADERS=true` only with verified ingress controlling toolbox and forwarded headers; it enables a valid toolbox IP then Fastify `request.ip` fallback. Fastify's broad `trustProxy: true` is not proof of trusted ingress. Cloudflare must actually control `CF-Connecting-IP`; mocked headers cannot prove provenance. The backend binds to loopback; ingress exposure is operator-managed.
- **SSRF and redirects:** backend HTTP/TLS validate hostname/port, block private/reserved destinations including mapped forms, and connect to validated IPs with hostname identity retained. HTTP rejects mixed blocked/public answers and revalidates each manual redirect; TLS filters blocked answers. DNS uses only fixed resolver endpoints, no custom resolver destination or bulk API. These controls do not replace network egress/ingress policy.
- **Registration lookup:** RDAP uses IANA HTTPS bootstrap, verified HTTPS/443 and pinned validated addresses; WHOIS discovers via IANA TCP/43 and follows bounded explicit registry referrals. Each destination is revalidated, rejecting private/reserved/mapped and mixed DNS answers. Queried IP registration identifiers are never connection destinations. Auto cannot bypass denial/rate limits, security rejection, timeouts or cancellation. WHOIS transport has no confidentiality/authentication; do not submit sensitive identifiers. Registration data is not purchase availability, verified geolocation or live DNSSEC validation. Shared process-local results have a 60-second cache TTL, with bounded discovery/result/rate caches and opportunistic expired-entry cleanup; no tracking/monitoring. Untrusted responses/links render as text and exports are explicit. See [registration limits and evidence](backend/REGISTRATION_LOOKUP.md).
- **Resource controls:** diagnostics have bounded admission, sockets, attempts, deadlines and rate history. DNS/HTTP caches/history are bounded and process-local; TLS has no result cache. Limits are not distributed across replicas. System DNS fallback cannot be forcibly cancelled, socket close is asynchronous, and synchronous parsing/certificate work cannot be preempted. See [API resource overview](docs/API.md#errors-admission-and-cancellation) and its detailed backend links.
- **Diagnostic limits:** DNSSEC flags/records are not independent cryptographic validation; DNS is UDP-only and truncated replies are incomplete. HTTP header findings are hints, not a full web security assessment. HTTP HTTPS verification stays enabled. TLS intentionally permits unauthorized connections to inspect bad certificates, reports authorization and hostname separately, and does not establish revocation, transmitted chain count/completeness, or a trust anchor from runtime issuer links. Certificate-type heuristics and “not known weak” algorithm observations are not security certification.
- **Operational privacy:** backend logging is enabled; HTTP failures can contain destination URL/address information. DNS/HTTP results are shared in-memory cache data. Keep production credentials outside the repository, review log access/redaction/retention, and do not submit confidential target names or URL credentials. See [operations](docs/OPERATIONS.md).

## Verification scope

Offline regression tests cover security/contract/resource boundaries; Chromium tests mock network diagnostics and guard external traffic. They do not prove production connectivity, Cloudflare identity authenticity, every browser's behavior, or full screen-reader compatibility. CSR browser tests disable trace/video/screenshots, avoid secret assertion diffs, clear the clipboard best-effort, and close the page before failure snapshots. See [CSR test protections](frontend/tests/csr/README.md).

No production access or external scan is authorized by this document. Changes to authentication, crypto, ingress, proxy trust or network policy require explicit review and appropriate offline regression coverage; consult [contribution guidance](CONTRIBUTING.md) and [production boundaries](docs/PRODUCTION.md).
